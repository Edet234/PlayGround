# Plan: JetX Multi-Platform Live Signal Engine & Tracker (Node.js backend + React/Tailwind frontend)

## 1. Goal
Rebuild the repo into a real-time tracker + signal generator: Node.js backend holding persistent WebSocket sessions to tokenized `ssgportal.com/*.aspx` feeds (with Simulation Mode fallback), broadcasting to a React + Tailwind "Command Center" dashboard covering 7 platforms (Stake, Linebet, Bangbet, 1xbet, Melbet, 888, Megapari).

## 2. Key decisions (need approval)
- **Frontend: React 18 + Vite + Tailwind + zustand**, hand-rolled `<canvas>` chart (ported, 10 ticks/s needs rAF control; chart libs resample badly). Vue is an acceptable fallback.
- **Realtime: `ws` (not Socket.io)** — raw WS, native browser client, lower latency, single `$PORT` server.
- **HTTP: plain `node:http` + `ws`, no Express** (30-line router is enough).
- **`start.sh` must be replaced**: current launcher only serves static files and cannot host a backend. New `start.sh` runs `vite build` then `node server/server.js`, which serves `dist/` + WS + REST on the same `$PORT`. Observable contract preserved (`bash start.sh` → `GET /` 200, respects `$PORT`).
- **Signal engine is authoritative on the backend**, mirrored on frontend from the same shared module.

## 3. Architecture
```
Browser (React)  ←WS /live + REST /api/*→  server/server.js (http + ws, $PORT)
                                                  ├─ sessionManager.js (1 active upstream per subscribed platform; switch = close old + open new, no refresh)
                                                  ├─ upstream.js (real ssgportal WS client + heartbeat/TTL watchdog)
                                                  ├─ simulation.js (SimEngine: port of current round machine)
                                                  ├─ signalEngine.js (re-export shared/signal.js + Strong/Weak)
                                                  ├─ tokenStore.js (env-seed → data/settings.json gitignored → memory; masked reads)
                                                  └─ routes.js (/healthz, /api/platforms|snapshot|history|settings, /api/admin/refresh-token|simulate-drop)
shared/ (imported by both sides via vite alias @shared)
  platforms.js (7 entries: name/slug/mark/color/color2/demo URL) · signal.js (drawCrash/stats/computeSignal) · protocol.js
```

## 4. Port existing logic verbatim (from `app.js`)
- Crash RNG: 6% instant bust 1.00–1.15, else `0.97/(1-u)`, cap 60x.
- Round machine: waiting 1200–3000ms → flying tick 100ms (`mult=exp(0.14·flightT)`, `flightT+=0.12`) → crashed → 1400ms pause.
- Signal momentum-v2 5-branch rules + `strength` added: `Strong` if `(BUY && conf≥70) || (WAIT && conf≥70)` else `Weak`. Output `{action, strength, conf, target, stake, risk, reason, momentum}`.
- Caps: history 60, strip 24, stats window 50, event log 60.

## 5. WS protocol (JSON, `type`-discriminated; all server frames carry `platform` + `serverTime`)
- Client → server: `subscribe{platform,clientTime}` · `unsubscribe` · `set_url{platform,url}` · `refresh_token{platform}` · `ping{clientTime}`
- Server → client: `snapshot` (full state: round, multiplier, players/staked, history, stats, signal, connection, tokenTtl) · `round_start{roundId,players,staked}` · `tick{roundId,multiplier,flightT}` (10Hz) · `round_end{roundId,crash,signal}` · `signal{roundId,signal}` · `connection{status: live|connecting|reconnecting|expired|lost|switched, latencyMs, mode}` · `token{ttl,status: ok|expiring|expired}` · `banner{kind: TOKEN_EXPIRED|CONNECTION_LOST|clear, text}` · `pong` · `error{code: BAD_URL|BAD_PLATFORM|UPSTREAM_401}`

## 6. Critical flows
- **Platform switch (no refresh):** click tile → instant re-brand (CSS vars) + `subscribe` → backend closes old upstream (code 1000) / stops sim, opens new (custom URL ? live : sim), resets TTL 120s → `connection{connecting}` → `snapshot` → tick stream.
- **Token expiry:** 1s sweeper; ≤20s `expiring`; 0 → close upstream, emit `token{expired}` + `connection{expired}` + `banner{TOKEN_EXPIRED}` same tick → frontend red flashing banner, pill red, beeps, stream frozen. Refresh → TTL 120 + resubscribe + snapshot.
- **Drop:** upstream abnormal close / `simulate-drop` → `connection{lost}` + `banner{CONNECTION_LOST}` immediately; backoff reconnect 1s/2s/5s; 3 fails → degraded sim.
- **Settings/Admin panel:** gear button → per-platform rows (mode badge, masked URL `…AB12`, TTL, paste-input, Save/Refresh/Test). Save → `POST /api/settings` (validates `^wss://…\.aspx\?token=.+`, else 400). Tokens never in query strings, logs, toasts, or git.

## 8. Verification
- `bash start.sh` on free `$PORT` → `GET /` 200, `/healthz` ok.
- `npm test` (RNG ~6% bust, cap 60, all 5 signal branches, conf≤94).
- REST smoke: `/api/platforms`, `/api/snapshot?platform=stake` (assert history+signal), bad-URL 400.
- WS smoke: `subscribe` → `snapshot` <500ms, ≥5 `tick`/2s, ping/pong p50 <100ms localhost; switch platform → new snapshot, no reconnect.
- Faults: `simulate-drop` → banner <300ms; refresh → TTL 120 + clear; `JETX_TTL_SECONDS=3` dev expiry → TOKEN_EXPIRED banner.
- Playwright screenshot: climbing multiplier, 24 chips, signal card, no blank canvas.
- Leak check: `rg token= dist/` shows only DEMO placeholders; `data/settings.json` untracked.

## 9. Known limitations
Single-process backend (no horizontal scale); live ssgportal frame format reverse-engineered at runtime (sim fallback); `ws` has no auth — gate `/api/settings` if publicly exposed.
